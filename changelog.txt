Cybermaps release history
=========================

7.4.2
-----

* Counted raw candidates before SEO evaluation: briefings share a 250-candidate budget across pinned and ordinary posts; summaries examine at most 1,000 candidates and disclose incomplete coverage.
* Fetched inventory batches as complete post rows, retained hydrated objects through URL/title and SEO helpers, primed pinned metadata, and stopped flushing unrelated runtime cache entries between batches.
* Serialized cached, forced, full, and localized LLMS generation with durable ownership leases and MySQL session fences where supported; cache invalidation and eviction cannot authorize another owner.
* Added a cooperative 20-second generation deadline, early pagination-progress checks, and uncached HTTP 503 responses with Retry-After when a build cannot complete. Failed builds never populate caches or replace static publications.
* Corrected candidate-scan reporting when SEO exclusions exhaust the inventory, and isolated localized publication caches.

7.4.1
-----

* Sanitized request flags, headers, OAuth callback values, and request paths at the input boundary.
* Prepared OAuth lookup column identifiers and documented intentional custom-table queries and bounded metadata lookups.
* Documented Cloudflare OAuth and specification links incorrectly flagged as offloaded assets by older Plugin Check versions.

7.4.0
-----

* Added opt-in managed .htaccess delivery with ownership-safe removal and routing diagnostics.
* Added per-publication server-side evidence and manual public inspection links.
* Corrected Cloudflare media types and root publication coverage.
* Fixed report comparison SQL parameters and exception handling.
* Fixed LLMS inventory pagination and expanded bounded full-corpus publication.

7.3.4
-----

* Isolated `/ai-discovery` from cross-site origin caches with an owned Cloudflare request-transform rule.

7.3.3
-----

* Added `/ai-discovery` to the ownership-safe default static inventory.
* Prevented stale nginx/FastCGI path caches from overriding the canonical discovery index on compatibility-mode sites.

7.3.2
-----

* Added a hashed installation identity to every Cybermaps APCu, Redis, Memcached, and object-cache key.
* Prevented independent WordPress installations that both use blog ID 1 from exchanging derived discovery payloads.

7.3.1
-----

* Fixed the invalid Cloudflare eligibility visibility helper that caused Advanced settings to fatal.
* Fixed automatic detection to hide and restore the complete manual-confirmation row.

7.3.0
-----

* Renamed System Status to Debugging and added opt-in, time-bounded diagnostic logging.
* Added redacted GitHub support bundles with copy, download, retention, and clear controls.
* Added aggregate static-publication and plugin-fatal instrumentation without collecting request analytics or credentials.

7.2.2
-----

* Added an exact-host Cloudflare eligibility gate that disables OAuth and API
  token mutations unless proxy traffic is detected or an administrator makes
  a page-scoped, nonce-protected manual confirmation.
* Added browser detection, distinct checking/failure/manual states, accessible
  guidance, and OAuth transaction host binding.

7.2.1
-----

* Fixed Cloudflare OAuth completion recovery and automatically verify public
  discovery resources from the administrator's browser with bounded retries.
* Added canonical subdirectory/headless paths, per-resource diagnostics, a
  Cloudflare execution marker, and complete OAuth metadata cache bypass.

7.2.0
-----

* Added public Cloudflare OAuth with PKCE, account consent, automatic combined
  rule installation, immediate token revocation, and no stored credential.
* Added a bounded open-source callback relay, ambiguity-safe zone selection,
  OAuth lifecycle status, and a collapsed one-time-token fallback.
* Added self-managed Cloudflare OAuth with a site-local callback, PKCE/state
  handoff, public-client settings, and exact registration guidance.

7.1.0
-----

* Added a System Status submenu that separates stack availability from the
  optimizations Cybermaps is actively using.
* Added one-time-token Cloudflare response-header and cache-safety rule
  management without storing edge credentials.
* Added independent default-on LiteSpeed and APCu controls, shared delivery
  diagnostics, and Cybermaps-scoped cache invalidation.

7.0.1
-----

* Added ownership-safe canonical `.well-known` body fallbacks for origins that
  bypass WordPress, without misreporting static media types as conformant.
* Unified OAuth metadata generation, bounded LLMS traversal, and normalized
  duplicate public response headers in discovery diagnostics.

7.0.0
-----

* Raised the minimum supported WordPress version to 7.1 and established one
  public Ability graph for native REST execution, MCP, WebMCP, OpenAPI, RFC
  9727 API Catalog discovery, and ARD capability discovery.
* Replaced the nested `/.well-known/.htaccess` writer with exact routes in
  WordPress's global rewrite layer. Apache and LiteSpeed rules are emitted
  before filesystem checks, while avoiding a physical well-known directory
  lets standard nginx front-controller routing reach WordPress.
* Added ownership-safe removal of the old marker block, one-time rewrite
  schema refresh, canonical protocol probes, and explicit delivery state.

6.6.1
-----

* Added an ownership-safe, automatically managed `/.well-known/.htaccess`
  routing bridge for header-sensitive discovery endpoints on compatible Apache,
  LiteSpeed, and OpenLiteSpeed origins.
* Added scheduled canonical API Catalog GET/HEAD verification, cache
  invalidation, and blocked-before-WordPress diagnostics.
* Kept nginx and other non-`.htaccess` servers untouched and refused to treat an
  extensionless wrong-MIME static API Catalog as RFC 9727 conformance.

6.6.0
-----

* Enriched the standardized RFC 9727 API Catalog with RFC 9264 Linksets for
  each advertised public API and added a bounded public health endpoint at
  `GET /wp-json/cybermaps/v1/health`.
* Published OAuth authorization-server and protected-resource metadata as pure
  OAuth metadata. Cybermaps does not claim OpenID Connect, emit fabricated OIDC
  discovery, or expose a fake JWKS.
* Added default-off user-claimed OAuth registration using RFC 8628 device
  approval and logged-in WordPress review. Auth.md publication is separately
  opt-in; no account or credential is created before user approval.
* Added the current experimental MCP Server Card at
  `GET /wp-json/cybermaps/v1/mcp/server-card` and requested scanner
  compatibility at `/.well-known/mcp/server-card.json`. Optional MCP remains
  separately advertised and disabled by default.
* Added the draft Agentic Resource Discovery catalog at
  `/.well-known/ai-catalog.json`, with `/ai-catalog.json` as a compatibility
  alias and only currently active capabilities in its payload.
* Added default-off, read-only WebMCP registration for site search, same-origin
  page Markdown, and discovery-resource listing. Unsupported browsers safely
  receive no registration.
* Added visible maturity badges, exact helper guidance, authoritative links,
  and accessible descriptions for standardized, draft, experimental, and
  vendor-convention controls.
* Added copy-ready nginx, Apache/OpenLiteSpeed, LiteSpeed Cache, Varnish, and
  reverse proxy/CDN rules. Cybermaps never writes deployment configuration.
* Added status language that separates Configured, Advertised, and Publicly
  verified state and identifies likely canonical `/.well-known/` interception
  when a compatibility alias works but the canonical URL does not.

* Added explicit, RFC-aware `Accept: text/markdown` negotiation for eligible

* Added LiteSpeed request safeguards and deployment guidance for LiteSpeed,

6.4.1

6.3.0
-----

* Added generation-fenced WordPress Cache API groups so internal publication,
  registry, route, and diagnostic caches can be invalidated by generation
  instead of broad transient deletion.
* Added automatic Redis and Memcached acceleration through conforming
  `object-cache.php` drop-ins without a direct vendor dependency; Cybermaps
  treats the WordPress Object Cache API as acceleration, not as a source of
  durability.
* Added optional APCu L1 acceleration for disposable per-process values. APCu
  is never used as an authoritative queue, lock, or ownership store.
* Moved IndexNow submission state to a durable database queue with dedupe,
  bounded retry metadata, and safe batching for enabled same-host URLs.
* Added edge-cache policy support aligned with RFC 9111 plus RFC 9530
  Repr-Digest diagnostics for public machine publications.
* Added LiteSpeed Cache integration that applies Cybermaps cache tags and
  purges owned publication URLs automatically when the LiteSpeed Cache plugin
  is present.
* Added protected, opt-in exact-URL Varnish PURGE integration. Cybermaps does
  not claim portable nginx purge support and does not mutate server config.
* Added advisory nginx, Apache, OpenLiteSpeed, Varnish, and CDN configuration
  snippets plus diagnostics that distinguish automatic plugin behavior from
  operator-managed cache/server routing.
* Added default-off trusted-proxy settings for a selected forwarded-IP header
  and trusted CIDR list; arbitrary forwarded headers remain untrusted.

Historical upgrade notices
==========================

6.3.0
-----

Cybermaps 6.3.0 adds internal cache generation fencing, object-cache/APCu
acceleration, durable IndexNow queueing, and edge-cache integrations. Redis or
Memcached support depends on a conforming WordPress object-cache drop-in. APCu,
trusted-proxy headers, and Varnish PURGE are optional and not durability
authorities. Review the diagnostics before enabling protected edge purges.

5.0.3
-----

Cybermaps replaces extensionless well-known publications with
zero-configuration dynamic endpoints and MIME-safe JSON compatibility files.
Unchanged files from the retired design are removed safely.

5.0.2
-----

OpenLiteSpeed sites now receive a narrowly scoped, ownership-tracked
`/.well-known/.htaccess` compatibility file so extensionless metadata is served
with its required response headers.

5.0.1
-----

Custom AI Instructions now publish consistently across compatible discovery
outputs. Cybermaps clears cached discovery data and schedules owned static files
for regeneration during the upgrade.

5.0.0
-----

This is a deliberate reset to one standalone Core architecture.
Removed pseudo-protocol URLs will return 404. Review AI Publishing settings,
regenerate static files, validate public endpoints, and create a new Reports
baseline after upgrading.
